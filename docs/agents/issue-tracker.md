# Issue tracker: Jira

Work for this repository lives in Consensys Jira. Design system work normally uses the DSYS project.

## Conventions

- Use Jira references such as `DSYS-123` as the canonical ticket ID.
- Read and update tickets through connected Jira tools when available.
- Create tickets in DSYS by default unless the user names another project.
- Include context, acceptance criteria, dependencies, and relevant GitHub links.
- Do not substitute a GitHub issue when Jira access is unavailable. Prepare a Jira-ready draft and ask the user how to publish it.
- GitHub pull requests are implementation and review surfaces, not the issue tracker.

## When a skill says "publish to the issue tracker"

Create a Jira ticket in the agreed project. Do this only when the user has approved publishing.

## When a skill says "fetch the relevant ticket"

Read the Jira ticket, its comments, linked issues, and current status.

## Wayfinding operations

- Use a Jira epic or parent ticket as the map.
- Use child tickets for decisions, research, prototypes, and tasks.
- Represent blocking edges with Jira's native "blocks" links.
- Claim work through the project's normal assignee and status workflow.
- Record the answer on the ticket before resolving it.
