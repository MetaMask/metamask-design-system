# ModalFooter

`ModalFooter` is the action area at the bottom of a modal. Use it for up to three actions — secondary, primary, and an optional tertiary action such as "Not now" — plus an optional slot above the buttons for inline form controls. Use a vertical layout so the tertiary button sits under the others. Do not use all three buttons with a horizontal layout.

Pass each label and click handler through its button props. The footer sets the variant for you. Use `Button` directly when an action needs a different variant, when you need more than three actions, or when the actions are not part of a modal footer.

```tsx
import { ModalFooter } from '@metamask/design-system-react';

<ModalFooter
  primaryButtonProps={{ children: t('confirm'), onClick: handleSubmit }}
  secondaryButtonProps={{ children: t('cancel'), onClick: handleClose }}
/>;
```

## Props

### `primaryButtonProps`

Props for the primary action button. Renders with `ButtonVariant.Primary` automatically. Appears after the secondary button (right in horizontal layout, below it in vertical layout) and above the tertiary button when one is set.

Pass the localized label as `children` and wire the click handler via `onClick`. `ModalFooter` is i18n-agnostic — pass localized strings from your application's i18n layer (e.g. `t('confirm')`).

### `buttonsAlignment`

Layout direction for the action button row.

- `ButtonsAlignment.Horizontal` (default) — buttons are laid out side by side. Do not use this alignment with all three buttons.
- `ButtonsAlignment.Vertical` — buttons are stacked. A tertiary button is last, under the others. Use this alignment when a tertiary button is set.

### `className`

Use the `className` prop to add custom CSS classes to the outer `<footer>` element. These classes are merged with the component's defaults via `twMerge`, so consumer utilities override the defaults (for example, `className="px-0"` wins over the internal `px-4`).
