# Card

Card is a container that groups related content on a surface. It provides padding, border, background, and the default text color only — no title, icon, or actions of its own.

Use it to separate a block of content from the page background. Place any content in `children`. For richer layouts (headers, rows, footers), compose those pieces inside the card rather than extending Card itself.

```tsx
import { Card, Text } from '@metamask/design-system-react';

<Card>
  <Text>Card content</Text>
</Card>;
```

### `onClick`

Optional click handler. When provided without `asChild`, the card stays a `div` and gains button affordances: `role="button"`, `tabIndex`, activation with Enter and Space, and hover and pressed surface styles. It stays a `div` rather than becoming a `button` so block-level content such as a `p` is still valid inside the card. With `asChild`, the handler is merged onto the child. Omit `onClick` for a static card.

For a card that navigates, prefer `asChild` with an `a` so the element carries its own semantics.

### `asChild`

Merge Card styles onto a child element instead of rendering a `div`. Use this when the card should be a link, a button, or another semantic element, since the child brings its own role, focus behavior, and keyboard activation. If `onClick` is also passed, it is merged onto that child. The child is made a full-width block so an inline element such as an `a` still forms a card-sized surface.

### `className`

Use the `className` prop to add custom CSS classes to the component. These classes will be merged with the component's default classes using `twMerge`, allowing you to:

- Add new styles that don't exist in the default component
- Override the component's default styles when needed

### `style`

The `style` prop should primarily be used for dynamic inline styles that cannot be achieved with `className` alone. For static styles, prefer using `className` with Tailwind classes.
