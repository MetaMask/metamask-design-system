# ModalContent

`ModalContent` is the centered dialog container that lives inside a `Modal`. It lays out the dialog surface inside the native `<dialog>` rendered by `Modal` (an `absolute inset-0` positioning wrapper, so it never competes with the `::backdrop`) and applies the standard `slide-up` entrance animation. Escape handling, focus containment and the `dialog` role/`aria-modal` come from the native `<dialog>` in `Modal`; `ModalContent` does not add its own listeners, focus trap, or nested `role="dialog"`.

`ModalContent` reads its behavior from `useModalContext`, so it must be rendered inside `<Modal>`.

```tsx
import { Modal, ModalContent } from '@metamask/design-system-react';

<Modal isOpen={isOpen} onClose={() => setIsOpen(false)}>
  <ModalContent>{/* ModalHeader / ModalBody / ModalFooter */}</ModalContent>
</Modal>;
```

### `modalDialogProps`

Props forwarded to the inner dialog `Box` (a plain `<section>`; the dialog semantics live on the native `<dialog>` in `Modal`). Use this to add `data-testid`, override layout, change background, or apply Tailwind utilities via `className`. Consumer `className` is merged with the component's defaults via `twMerge`.

## Behavior controlled via `Modal`

These flags are configured on `Modal` and handled there with the native `<dialog>`:

| Flag                     | Effect                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| `isClosedOnEscapeKey`    | When `true`, pressing Escape (the native `cancel` event) calls `onClose`.                  |
| `isClosedOnOutsideClick` | When `true`, a click on the backdrop or the empty area around the content calls `onClose`. |
| `autoFocus`              | When `true`, the native dialog focus step focuses the first focusable child on open.       |
| `initialFocusRef`        | When set, this element receives focus on open.                                             |
| `finalFocusRef`          | When set, this element receives focus on close.                                            |
| `restoreFocus`           | When `true`, focus returns to the element that opened the modal.                           |

## Outside-click opt-out

Outside clicks are detected by `Modal` (a click that starts and ends on the backdrop, the `<dialog>`, `ModalOverlay`, or the empty area around the content). Clicks whose target's `closest('[data-mm-modal-ignore-outside-click]')` is non-null are ignored. Set the attribute on an element rendered **inside** the modal to opt out:

```tsx
import { MODAL_CONTENT_IGNORE_OUTSIDE_CLICK_ATTR } from '@metamask/design-system-react';

<Box {...{ [MODAL_CONTENT_IGNORE_OUTSIDE_CLICK_ATTR]: '' }}>
  {popoverContent}
</Box>;
```

The constant resolves to the literal string `data-mm-modal-ignore-outside-click`. The attribute presence is what matters — the value is unused.

> Floating UI that is portaled to `document.body` is outside the `<dialog>`: it is inert and painted below the top layer while the modal is open, so the attribute cannot help there. Render such elements inside the modal subtree.
