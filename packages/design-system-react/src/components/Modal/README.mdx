# Modal

`Modal` is the root of the modal component family. It renders a native HTML `<dialog>` and opens it with `showModal()` while `isOpen` is `true`, so the browser provides the top layer (no portal or z-index needed), an inert page behind the modal, focus containment, the `dialog` role with `aria-modal`, and the `::backdrop` scrim. It also provides a context that exposes the modal's behavior configuration (close-on-outside-click, close-on-escape, focus management) to any descendant via `useModalContext()`. When `isOpen` is `false`, the subtree is unmounted entirely so focus state and side effects are released.

`Modal` is intentionally a thin shell. Compose it with `ModalContent`, `ModalHeader`, `ModalBody`, and `ModalFooter` to assemble a full modal UI. `ModalOverlay` is optional: the native `::backdrop` already dims the page.

### Behavior notes

- **Escape** is handled through the dialog's native `cancel` event. The browser is never allowed to close the dialog on its own: `isOpen` stays the single source of truth and `onClose` is called only when `isClosedOnEscapeKey` is `true`.
- **Outside click** closes the modal when a click starts and ends on the backdrop, the `<dialog>` itself, `ModalOverlay`, or the empty area around `ModalContent`.
- **Accessible name and description**: `ModalHeader` labels the dialog (`aria-labelledby`) and `ModalBody` describes it (`aria-describedby`) automatically. Pass `aria-labelledby` / `aria-describedby` (or `aria-label`) to `Modal` to override.
- **Floating UI in portals**: everything outside the `<dialog>` is inert and painted below the top layer. Render popovers, tooltips and dropdowns that must be interactive inside the modal as descendants of `Modal` (or use the Popover API / another top-layer mechanism).
- **Scroll lock**: native modal dialogs do not lock page scrolling; `Modal` does not add scroll locking.

```tsx
import {
  Modal,
  ModalBody,
  ModalContent,
  ModalFooter,
  ModalHeader,
  ModalOverlay,
} from '@metamask/design-system-react';

<Modal isOpen={isOpen} onClose={() => setIsOpen(false)}>
  <ModalOverlay />
  <ModalContent>
    <ModalHeader
      onClose={() => setIsOpen(false)}
      closeButtonProps={{ ariaLabel: 'Close' }}
    >
      Modal Header
    </ModalHeader>
    <ModalBody>ModalBody children</ModalBody>
    <ModalFooter
      primaryButtonProps={{
        children: 'Confirm',
        onClick: () => setIsOpen(false),
      }}
      secondaryButtonProps={{
        children: 'Cancel',
        onClick: () => setIsOpen(false),
      }}
    />
  </ModalContent>
</Modal>;
```

### `className`

Use the `className` prop to add custom CSS classes to the root `<dialog>` element. By default it is reset to a transparent, full-viewport container (`fixed inset-0 m-0 h-full w-full max-w-none border-0 bg-transparent p-0`) with a `backdrop:bg-overlay-default` scrim; override the scrim with e.g. `backdrop:bg-black/60`. These classes are merged with the component's defaults via `twMerge`.

## `useModalContext`

`Modal` exposes its behavior configuration via context. Sibling/descendant components in the modal family can read it to decide how to react to clicks, keypresses, and lifecycle events:

```tsx
import { useModalContext } from '@metamask/design-system-react';

function MyCloseButton() {
  const { onClose } = useModalContext();
  return <button onClick={onClose}>Close</button>;
}
```

Calling `useModalContext()` outside of a `<Modal>` subtree throws a developer-friendly error.
