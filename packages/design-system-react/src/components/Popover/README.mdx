# Popover

`Popover` is a floating layer anchored to a reference element. Use it for menus, tooltips, and other contextual content attached to a trigger. Control it with `isOpen` and keep it in sync with `onClose`.

`Popover` uses the native [Popover API](https://developer.mozilla.org/docs/Web/API/Popover_API) and has no positioning-library dependency:

- **Top layer.** The root renders with the `popover` attribute and is shown with `showPopover()`, so it is painted above all page content, including modal `<dialog>`s. Ancestors with `overflow: hidden`, `transform`, or their own stacking context cannot clip or cover it, and no `z-index` is needed.
- **Native dismissal.** By default (`popover="auto"`) the browser closes the popover on a click outside, on Escape, and when another dismissible popover opens. `onClose` reports those closes.
- **Positioning.** A small built-in utility places the popover at `position`, flips it to the opposite side when it would overflow the viewport, and shifts it along the reference edge to stay on screen. It updates on scroll, resize, and size changes of the reference or popover. While the reference is scrolled out of view, the popover is hidden.

```tsx
import { Popover, PopoverPosition } from '@metamask/design-system-react';

const [referenceElement, setReferenceElement] = useState<HTMLElement | null>(
  null,
);
const [isOpen, setIsOpen] = useState(false);

<button ref={setReferenceElement} onClick={() => setIsOpen(!isOpen)}>
  Menu
</button>
<Popover
  isOpen={isOpen}
  onClose={() => setIsOpen(false)}
  referenceElement={referenceElement}
  position={PopoverPosition.BottomEnd}
>
  Popover contents
</Popover>;
```

### `onClose`

Called when the browser closes the popover: a click outside, the Escape key, or another dismissible popover opening. It is driven by the native `toggle` event. Set `isOpen` to `false` here so state matches what is on screen. It is not called when the popover closes because `isOpen` became `false`.

Clicking the trigger while the popover is open is safe to wire as a toggle (`setIsOpen(!isOpen)`): the trigger's click handler runs first and unmounts the popover, so `onClose` does not reopen it.

### `isDismissible`

Whether the browser may close the popover. `true` renders `popover="auto"`: clicks outside, Escape, and opening another dismissible popover close it, and `onClose` fires. Only one dismissible popover is open at a time, unless one is nested inside another.

Set it to `false` (`popover="manual"`) when the popover must stay open until `isOpen` changes: hover or focus tooltips, onboarding hints, or several popovers that are open at once. Manual popovers do not close other popovers and ignore clicks outside and Escape.

### `className` and `style`

Merged onto the popover root. `style` is applied after the computed position, so use it for sizing, for example `style={{ width: referenceElement?.offsetWidth }}` to match the trigger width. All other native `div` props (`id`, `aria-*`, `data-*`, event handlers) are forwarded.

## Behavior

### Top layer

The popover is shown in the top layer even when rendered inline, so ancestors with `overflow: hidden` do not clip it. Render `Popover` next to its trigger; no portal is needed.

<Canvas of={PopoverStories.TopLayer} />

### Hidden reference

The popover follows its reference while you scroll, and is hidden (`visibility: hidden; pointer-events: none`) while the reference is scrolled out of view, including out of a scrolling ancestor.

<Canvas of={PopoverStories.ReferenceHidden} />

### Inside a modal dialog

Render the popover inside the `<dialog>`, next to its trigger. It is shown in the top layer above the dialog and is not inert. Escape closes the popover first, then the dialog. A click outside the popover but inside the dialog closes only the popover. Opening a modal dialog closes any open dismissible popovers.

Do not portal popovers out of a modal dialog: content outside a dialog opened with `showModal()` is inert, so a portalled popover cannot be clicked.

<Canvas of={PopoverStories.InsideDialog} />

### Browser support

The Popover API is supported in Chrome 114+, Firefox 125+, and Safari 17+. Positioning is done in JavaScript because [CSS anchor positioning](https://developer.mozilla.org/docs/Web/CSS/CSS_anchor_positioning) with fallbacks (`position-try-fallbacks`) needs Chrome 128+ and Firefox 147+. Once the supported browsers reach those versions, the positioning utility can be replaced with CSS.
